This page renders the diagrams of the test models *Threat model - Layered test project*, which uses the layout _Zones in tree order_, and *Threat model - Grouped test project*, which uses the default layout _Follow the dataflows_ with groups. Compare each diagram with the checklist below it. The logic behind the diagrams is tested with assertions (see _Testing - threat modelling_); this page checks what only a picture can show.

What correct looks like:

* Five rows from top to bottom: _Enterprise zone_; _DMZ_; _Operations zone_; _Control network_ with _Cell A zone_ and _Cell B zone_ side by side; _Safety zone_ and _Field zone_ side by side.
* _Plant site_ is a grey dashed frame around rows 2 to 5. It does not reach up into the enterprise row. The other boundaries are red.
* _Corporate user_ and _Remote vendor engineer_ are in the top row, _Vendor cloud_ in the DMZ row, _Control room operator_ in the operations row and _Field technician_ in the control row.
* All dataflows are black, including _Remote support [4G VPN]_ from the remote vendor engineer to _PLC B_, which skips rows.
* _Replicate history [PI-to-PI]_ points up from _Historian_ to _Historian mirror_, without a long loop.
* Labels of dataflows to interfaces end with the port, such as _Commands [Modbus TCP] (502/tcp)_.
* _Safety and field level_ is a grey rectangle with its title around _Safety zone_ and _Field zone_, in the bottom row. The hidden group _Off-site parties_ is not drawn, and its members stay in their own rows.
